# Crowd Bet Insight

פלטפורמה ל"חוכמת ההמונים" בהימורי ספורט: שילוב בין משחקים ויחסים חיים, דיווחי קהילה על סכומי הימור, ופיד שמציג לאן הכסף זורם בזמן אמת.

## מה כבר קיים בפרויקט

- `React + Vite` לפרונט.
- `Supabase` לאימות משתמשים, בסיס נתונים ו־Realtime.
- Edge Functions למשיכת יחסים חיים דרך `The Odds API`.
- טבלת `bets` שבה משתמשים יכולים לדווח כמה כסף שמו, על מה, ובאיזה בוקמייקר.
- View בשם `crowd_game_summary` שמאגד את דיווחי הקהילה ברמת משחק.

## הארכיטקטורה הנכונה למוצר שלך

### 1. שכבת נתוני ספורט חיים

- משחקים, סטטוס, שעת פתיחה ותוצאות חיים.
- יחסים חיים מכמה בוקמייקרים.
- בהמשך: חיבור גם לזרימות כסף חיצוניות מאתרים/ספקים שמספקים market splits או bet percentage.

### 2. שכבת חוכמת ההמונים

כל משתמש מדווח:

- על איזה משחק הימר
- על איזה צד
- כמה כסף שם
- באיזה יחס
- דרך איזה אתר/בוקמייקר

הנתונים נשמרים ב־`public.bets` ומסוכמים ב־`public.crowd_game_summary`.

### 3. מה רואים באתר

- כמה כסף הקהילה שמה על כל צד במשחק
- כמה דיווחים יש לכל משחק
- מגמות כסף בזמן אמת
- השוואה בין "לאן הקהילה הולכת" לבין "לאן השוק הולך"
- בעתיד: התראה כשיש פער בין דעת הקהל לבין תנועת הכסף החיצונית

## מה עדיין חסר כדי להגיע לחזון המלא

- חיבור GitHub אמיתי לפרויקט הזה.
- ספק נתונים חיים רחב יותר ממשחקי EPL בלבד.
- מזהה משחק אחיד (`game_id`) שמוזן אוטומטית מהלוח החי לתוך טופס הדיווח.
- נרמול שמות קבוצות/ליגות כדי שדיווחים תמיד יתחברו למשחק הנכון.
- חיבור לנתוני "money flow" חיצוניים, אם יהיה API או ספק מורשה לכך.
- מנגנוני אמון: אנטי־ספאם, הגבלת מניפולציות, דירוג אמינות משתמשים.

## השלב המומלץ הבא

1. לחבר את הפרויקט הזה ל־GitHub.
2. לחבר את Supabase לפרויקט production מסודר עם סודות (`ODDS_API_KEY`).
3. לשדרג את טופס הדיווח כך שייבחר משחק חי מהרשימה במקום הקלדה ידנית.
4. לחבר עוד ספקי ספורט חיים.
5. לבנות מסך מרכזי של `Crowd vs Market`.
